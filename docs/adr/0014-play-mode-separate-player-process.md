# Play Mode runs in a separate Player process

**Play Mode** is a try-the-game session owned by a dedicated **Player** executable (`engine_player`: thin main over the shared engine runtime), not an in-editor simulation that mutates the authorship `SceneInstance`. The editor stays in **Edit Mode**, may keep editing, and drives at most one **Play session** via Play / Pause / Stop / Reload over a **local IPC control channel** (pause skips Behaviour Tick while the window stays viewable; stop and closing the Player window end the process; **Play Reload** reinstantiates the captured On-disk **Play entry scene** in that same process — [ADR 0047](0047-play-reload.md)). Play loads the **saved** active scene asset (dirty documents get Save and Play / play last saved / cancel); the editor builds Project `Scripts/` when dirty before spawn. Dumping the Live `SceneInstance` into the Player, ALC hot-reload, and Player-side Asset hot-reload stay out of the first bridges. Sealed Live-document Commands may reach the running world as **Play authorship patch** ([ADR 0048](0048-play-authorship-patch.md)). The editor viewport may show Tick-driven poses as **Play pose preview** without writing Live ([ADR 0049](0049-standalone-play-preview-and-patch.md)). Edit Mode does not start a .NET script host for normal authorship — gameplay peers and Tick run in the Player (env-gated editor host remains debug/test only). Rejected for this product shape: in-editor Play in the authorship viewport; same-process PIE or a second Game window as the Play boundary; Unity in-place Tick; reusing `engine_editor --play` as the long-term Player; auto-save-only or silent dirty Play; requiring Live dump or ALC before Play UI ships.
