# DogWalk animation Phase 5: modifiers, method tracks, BlendSpace2D, Tree Asset

DogWalk animation Phase 5 needs post-pose procedural bones, clip method events, Pinda-style BlendSpace2D, and reusable tree authorship without full Godot parity or a cutscene director. We decided **one milestone with three independent Done gates** (implement order A→C→D): **(A)** ordered **SkeletonModifier** chain after Player/Tree sample and before PoseApplied (extension point + test double + one LookAt/aim sample) plus **method tracks** in clip YAML with key-crossing dispatch on the **base dominant-clip clock** to Behaviours/Message (not PtrCall); **(C)** **BlendSpace2D** via triangulation + barycentric TRS blend and per-node `(x,y)` API; **(D)** **AnimationTree Asset** (GUID) + Inspector topology as D-core (visual canvas optional), with **Asset as base** and **small scene instance overrides** when referenced (embed-only when no Asset). Audio tracks, Cubic/Bezier, cross-Object Skeleton drive, and canvas-as-Done are out. Lean Play bars per gate; Edit may scrub A/C/D engine state without Behaviour Tick.

**Considered options:** Phase 5a/b/c split; PoseApplied-only C# bone hacks; PtrCall method tracks; grid-only or nearest-three 2D blend; visual canvas as D Done; mutual exclusion Asset vs embed; engineering-only Done. Rejected for DogWalk feel gaps, API mismatch with Blunder Behaviours, or blocking A/C on editor scope.
