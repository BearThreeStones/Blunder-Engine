# Detection Action + Editor Mesh Hot Reload

**Asset Watch** stays the on-disk detector for Project `Assets/` and `Resources/` (not a replacement for manual **Reimport**). Matched Source-archive and Intermediate-direct changes (including glTF sidecars: sibling `.bin` and glTF-relative textures) share one **Detection Action** editor-user preference: default **Prompt** (one coalesced toast → Reimport All / Dismiss) or **Auto** (debounced Reimport without prompt). This **supersedes** today’s silent always-Auto Reimport for `Resources/Source/` only. Intermediate overwrites run Detection → Reimport (not Final-invalidate alone), so Intermediate-direct Assets refresh derived data. After a successful Reimport, v1 **Editor Asset Hot Reload** refreshes loaded Mesh presentation in the current editor session (AssetManager / viewport / Mesh Preview / placed scene meshes). Out of scope for this ADR: Project-external watch roots, AnimationClip/AnimationPlayer live hot-swap, forced Cook on every Reimport, per-asset Prompt pickers, and per-Project Detection Action as the preference home.

**Status:** accepted (docs first; Watch / Prompt / Hot Reload code follows)

**Considered options:** Replace manual Reimport with watch-only updates (rejected — settings-only and selective refresh still need Reimport). Keep Source silent-Auto while Intermediate uses Prompt (rejected — two policies). Intermediate overwrite = invalidate Final only (rejected — leaves Clip YAML / derived Intermediate stale). Editor Asset Hot Reload includes Clip playback swap and immediate Cook in v1 (rejected — defer; Mesh session refresh is the first visible slice). Project-level Detection Action (rejected for v1 — personal workflow noise). External DCC watch roots in v1 (rejected — separate milestone).
