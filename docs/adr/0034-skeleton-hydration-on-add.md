# Add… hydrates Skeleton from the entity’s skinned mesh glTF

When Add… creates a Skeleton on the selected Object (directly or via host cascade), rest/bind is filled from that entity’s skinned mesh Intermediate glTF onto the **same** Object so AnimationPlayer can deform without a scene reload. Static meshes and failed reads still create an empty Skeleton (warn, do not fail the Add). Scene load (`SceneSystem::instantiateScene`) also hydrates empty Skeletons on Objects that already have AnimationPlayer or AnimationTree, after mesh attach, because bones are not serialized in the scene file. Scene Thumbnail instantiate uses the same attach+hydrate sequence so stills are not an empty-Skeleton T-pose. Rejected: empty-only Skeleton as the skinned Add Player path, expanding `importUnderEntity` children as a side effect of Add Skeleton, and requiring a separate Skeleton Asset (ADR 0031).
