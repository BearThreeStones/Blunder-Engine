# Physics Kernel: self-built Q32.32 lockstep core

Blunder needs rigid-body simulation that can later support **frame-sync / lockstep** multiplayer. We decided to **author a native Physics Kernel** (not adopt Jolt/PhysX/Bullet as the lasting solver), stepped in an isolated **Physics World** with fixed `dt = 1/60`, verified by a **numeric golden suite** (plus module unit tests). Simulation uses engine-owned **Q32.32 fixed-point** math (no platform `libm` / float `glm` on the hot path) so Win MSVC x64 and Linux Clang/GCC x64 produce **bit-identical** World state. Kernel v0 covers Dynamic/Static/Kinematic (pose-delta velocity), convex colliders, materials, stacking, and per-body sleep — not CCD, joints, meshes, character API, or scene projection. Gameplay/Character APIs stay deferred; the first post-v0 milestone is a thin **scene bridge**. Domain terms: [CONTEXT.md — Physics](../../CONTEXT.md).

**Considered options:** Character-first / query-only first slice; third-party float solver as truth; SceneInstance- or ECS-hosted body state for v0; variable dt; float or Q22.10 scalars; same-machine-only determinism; deferring cross-platform bit identity until netcode. Rejected because lockstep diverges under IEEE float across toolchains, and coupling v0 to scene/ECS or game APIs blocks a closable golden loop.
