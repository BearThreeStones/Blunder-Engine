# DogWalk animation Phase 7: AnimationTree Canvas + conditional StateMachine transitions

Phase 4–6 deferred a visual AnimationTree editor; Phase 5 D shipped **AnimationTree Asset** + Inspector (canvas optional). Authors still need a graph UI, and DogWalk needs **parameter-driven** automatic state changes beyond script-only Travel. We decided **DogWalk animation Phase 7**: ship **AnimationTree Canvas** v1 whose **truth source is the AnimationTree Asset** (not scene-embed); **dual-track** with Inspector; **layout-in-Asset**; **topology-only** preview (bound preview character is follow-up); open from **Asset browser and Object Inspector**. Canvas covers Phase 5 nodes (**StateMachine**, **BlendSpace1D/2D**, **OneShot**, **Add2**). StateMachine gains **real transition edges**: hybrid condition inputs (existing named drives + independent bool/float tree params), **single predicate** per edge (`param op value`), author **priority** on multi-true outs, **hard-cut** switches, **Travel/Start coexist**. **Done:** engineering + Edit authorship **plus** lean Play bar (perceptible auto state change via conditions; test rig/subset OK). Does not cancel open Phase 1–6 content gates. Out: Godot-complete trees, clip-end-only as sole trigger, per-edge fade, AND/OR expressions on one edge, canvas-as-embed editor, removing Inspector topology.

**Considered options:** Asset-only vs embed/both canvas truth; lean-1D vs Phase-5 full node set; Inspector demotion; layout in local prefs; live in-canvas preview as Done; decoration-only edges; clip-end or full expression transitions; Travel-only after edges; BlendSpace-only condition inputs; declaration-order or forbid-overlap conflicts; edge Crossfade via Player slots; Phase 5 patch vs unnumbered change; engineering-only Done. Rejected for dual truth sources, Pinda/2D authorship split, blocking existing Inspector flows, nondeterministic or oversized runtime/editor scope, or silently reopening closed phase Done bars.
