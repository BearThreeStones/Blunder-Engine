# Inspector Behaviour UX is declaration-authoritative with a build-time type catalog

Edit Mode authors Behaviours in the Inspector against the scene **Behaviour declaration** (ordered type + BehaviourId + bool/number/string property bag), not against a live Script Peer. **Mount** (`AttachBehaviour` / `mountSceneBehaviours`) stays a Play/Player step (or env-gated debug host), matching ADR 0014. The Add picker and property forms use a **Behaviour type catalog** scanned from the Project Scripts assembly metadata after a successful `dotnet build` — no CoreCLR host required for authoring. Catalog includes public bool/number/string member metadata so forms are catalog-driven; missing types stay visible as broken entries (removable, not auto-dropped, not Save/Play blockers). Add, Remove, drag reorder, and property commits are Document History Commands on `EntityId`. Rejected for this slice: live-peer-required authoring, editor host as the product Add path, Vec3/enum/nested/asset editors, silently dropping unknown types, and treating AttachBehaviour as the Inspector edit API.
